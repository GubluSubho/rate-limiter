Algorithm on this endpoint

Sliding window counterTwo counters (this minute and last minute). Estimate = last * overlap + current. Very little memory, but approximate.
Token bucketA bucket of 5 tokens that refills steadily. Each request takes one token. Allows short bursts, then a steady rate.
Sliding window logStores the timestamp of every request in a sorted set. Exact count over the last 10 seconds, but uses more memory.

How to read this

Each request goes through the limiter before it reaches the route. The limiter runs a Lua script inside Redis that counts, decides and updates in one atomic step. If the answer is no, the server replies 429 with a Retry-After header.

Note that /login and /search also pass through the global limiter first, so use the Pro identity for those two to see their own limits clearly.
