What is a rate limiter?

It is a bouncer for your server. It decides how many requests one person may send in a given time, so nobody can overload the server.

1

A request arrives

A browser, app or script asks your server for something.
2

The limiter checks

It asks Redis how many requests this client already made recently.
3

Allow or block

Under the limit: the request goes through (200). Over the limit: it is rejected with 429.
Think of a club door. The rule is "10 people per minute". The bouncer keeps a count. Person 11 has to wait outside until the count goes down. A rate limiter does exactly this, but for requests, and it must count correctly even when hundreds of people arrive at the same moment.

What if Redis crashes?

A design choice every real system must make.

Main door (fail-open): if the memory database is down, the server keeps working with a small backup counter inside itself. Users are not locked out, but limits are less exact.

/login (fail-closed): if the database is down, the server refuses everyone with a 503. Safer for sensitive doors, because it never lets unlimited password guesses through.

Words you will see

Request
One message from a client asking the server to do something.
Limit
The most requests one client may send in one time window.
429 Too Many Requests
The standard error code for "you are over the limit".
Retry-After
A header telling the client how many seconds to wait.
Burst
Many requests sent almost at the same moment.
Atomic
Done in one indivisible step. The check and the count happen together, so two simultaneous requests can never both sneak in under the limit.
Fail-open / fail-closed
What to do when the limiter itself breaks: let traffic through (open) or refuse it (closed).
